# Song Guess UI regression

- Date: 2026-09-10 (Asia/Seoul, KST)
- Symptoms: The automatic pool flow immediately created a multiple-choice, title-only session. Teachers could not review prepared answers or independently select the answer target and answer mode. During guessing, the teacher timer disappeared when a round had no clip or a non-audio legacy clip.
- Impact: Automatic and saved setups did not follow the documented preparation and review flow, and the teacher could lose the visible round countdown for malformed or legacy media.
- Evidence: `prepareAutoGame` reset the settings to `multiple-choice` and `title` before calling session creation. The timer was rendered only inside the audio player's teacher branch, while `SongGuessGame` mounted that player only when a clip existed.
- Cause: The approved visual redesign moved setup controls out of the automatic preparation screen and coupled preparation to session creation. It also coupled the teacher timer to valid audio rendering.
- Timeline: The regressions were identified during local review on 2026-09-10 KST. The first repair pass stopped at 23:02 KST when the selected Sol worker returned a capacity error; no source rollback occurred. A continuation inspected the existing patch, completed the remaining integration corrections and verification, and retained the approved visual layout.
- Response: Restored shared setup controls for automatic and manual flows, kept prepared answers available for review, and made session creation a separate retryable action using the selected target and mode. The default answer mode is text, manual save keeps the established validation feedback for incomplete drafts, and failed creation retains the selected settings. A shared teacher timer now covers audio, missing, and non-audio rounds exactly once.
- Recovery verification: Focused component tests cover automatic preparation without immediate creation, answer review, independent title/artist/combined and text/multiple-choice selection, creation retry, incomplete-draft save validation, preparation callback sequencing, and missing, non-audio, and audio timer cases. Line-limit and whitespace checks are part of the same local recovery pass.
- Follow-up: Run authenticated teacher and student browser acceptance, persisted setup reload, and real audio playback before rollout. No live validation, database change, deployment, or production claim was made in this recovery.

## 2026-09-11 KST tablet follow-up

- Scope: Rechecked the repaired teacher setup and live guessing UI in headless Chrome with the real `SongGuessSetupControls`, `SongGuessAnswerGuide`, `SongGuessGame`, player, timer, scoreboard, and compiled CSS. A stateful host fixture supplied realistic setup, round, choice, and participant data. The automatic pool-fetch card and `SongGuessBoard` network lifecycle were outside this geometry fixture; existing focused Board tests remain the integration evidence for those paths.
- Paired rotation evidence: The same mounted automatic and manual setup UI was resized from 800×1280 to 1280×800 and from 768×1024 to 1024×768. In all four transitions, the combined artist/title target, multiple-choice mode, and open teacher answer guide remained selected. Required settings, answer review, create action, and manual editor stayed in the document and reachable by page scroll.
- Geometry evidence: Browser client/document widths matched at 785/785, 1265/1265, 753/753, and 1009/1009 CSS pixels after the reserved scrollbar gutter. Across automatic setup, manual setup, and live teacher guessing, there was no horizontal overflow, required-element clipping, or overlapping action rectangle. Document heights ranged from 1159 to 2297 CSS pixels and were reachable through normal page scrolling.
- Short-wide evidence: At 932×430 (917 CSS-pixel client width), automatic setup, manual setup, audio guessing, missing-audio guessing, and legacy non-audio guessing had no horizontal overflow, clipping, or action overlap. Their scroll heights were 1468, 1296, 1792, 1718, and 1760 CSS pixels respectively.
- Timer evidence: Live audio guessing rendered exactly one teacher timer in both tablet orientations. The 932×430 audio, missing-audio, and legacy non-audio cases also rendered exactly one timer each.
- Evidence files: `tmp/songguess-tablet-entry.tsx`, `tmp/songguess-tablet-geometry.mjs`, and `tmp/songguess-tablet-report.json`.
- Result: No tablet responsive source defect was reproduced, so this follow-up did not alter the approved Song Guess CSS or component behavior.
- Limitations: This was browser viewport resizing, not physical tablet rotation. Physical touch behavior, native or hardware keyboard behavior, Korean IME composition, authenticated Board API traffic, and real audio playback remain unverified.

# Aura Board 공통 게임 UI·전적 플랫폼 계약

## 목표

놀이보드를 일반 보드 디자인에서 분리해 목적형 게임 UI로 전환한다. 현재 `PLAY_LAYOUT_IDS`의 정식 범위는 `kordle`, `speed-game`, `shadow-alliance`, `omok`, `song-guess` 다섯 종류다. 각 게임의 규칙과 플레이필드는 유지하되 입장, 대기, 진행 HUD, 종료 확인, 결과, 재도전, 개인 전적 확인은 웹과 모바일에서 같은 계약과 디자인 언어를 사용한다.

`quiz`, `breakout`, `vibe-arcade` 등 게임처럼 보이는 수업형 레이아웃은 현재 PLAY 분류에 자동 편입하지 않는다. 구현 중 실제 세션·승패·종료 의미가 있는지 감사하고, 분류 변경은 근거와 마이그레이션 영향이 명확할 때만 한다.

## 상시 게임 허브 경계

- 학생 놀이 목적지는 `/api/student/boards` 결과와 무관한 정적 5종 카탈로그다. 교사가 만든 놀이 보드가 0개이거나 수업 보드 목록 로딩이 실패해도 웹과 Expo에서 게임명, 설명, 생성 아트, `상시 입장` 상태와 입장 행동을 표시한다.
- 카탈로그 순서와 메타데이터는 `src/lib/game-platform/catalog.ts`가 웹 기준이며 `apps/mobile/lib/game-platform-contract.ts`가 동일 wire value, 설명, artwork key, 상태와 route segment를 미러링한다. 계약 테스트가 두 표현의 완전한 일치를 확인한다.
- 실제 권위형 런타임은 기존 `boardId` 격리 경계를 유지한다. `POST /api/student/game-hub/entry`는 인증된 학생의 학급과 canonical game kind만 사용해 `Board.systemGameKind`가 표시된 내부 방을 지연 생성하거나 재사용한다. `(classroomId, systemGameKind)` 유일 키가 웹·모바일 동시 최초 입장 경쟁을 직렬화한다.
- 내부 방은 일반 교사 제작 보드가 아니다. 학생 보드 목록과 학생 홈 payload에서 제외하고, 서버가 해당 학급 교사를 `owner`로 연결해 문제·참가자 설정이 필요한 게임의 권한 있는 관리 경로는 유지한다.
- 입장 요청 스키마는 strict이며 점수, 시간, 참가자, 호스트나 런타임 상태를 받지 않는다. 완료 결과는 기존 authoritative session/run과 append-only `GameResult` 투영에서만 확정한다.
- 생성 PNG 원본 5개는 정식 앱 자산인 `public/game-hub/*.png`로 배치한다. 웹과 Expo는 같은 공개 정적 경로를 직접 사용해 자산 드리프트와 로컬 `.ai-bridge` 의존을 방지한다.
- `20260802160000_game_ui_platform` 마이그레이션은 `systemGameKind` 체크와 유일 인덱스를 포함하지만 이 구현 작업에서는 어떤 환경에도 적용하지 않는다.

## 공통 제품 계약

1. 게임 입장
   - 학생은 게임 규칙, 참가 상태, 연결 상태와 준비/입장 행동을 명확히 본다.
   - 교사/호스트 제어와 학생 행동을 권한별로 분리한다.
   - 로딩, 빈 세션, 오류, 재연결, 만석/참가 불가 상태를 제공한다.
2. 게임 진행
   - 공통 HUD는 게임명, 라운드/단계, 시간(해당 시), 점수, 연결 상태, 규칙, 안전한 나가기를 제공한다.
   - 핵심 플레이필드가 화면의 주인공이며 일반 보드 헤더·카드 UI를 중첩하지 않는다.
   - 서버 권위 게임은 기존 권위 상태와 idempotency를 유지한다.
3. 종료
   - 정상 완료, 승/패/무, 기권, 중도 이탈, 호스트 종료, 연결 끊김을 구분한다.
   - 결과는 중복 저장되지 않고 동일 게임 종료를 여러 번 수신해도 한 건만 확정된다.
   - 결과 화면은 게임별 지표와 공통 행동 `다시 하기`, `게임 목록`, `나의 전적`을 제공한다.
4. 개인 전적
   - 학생 놀이 영역에 `게임` / `나의 전적` 탭 또는 동등한 명시적 탭 구조를 웹·모바일 모두 제공한다.
   - 본인만 자신의 상세 전적을 볼 수 있다.
   - 게임 필터, 기간 필터, 총 플레이, 승/완료 수, 최고 점수, 최근 기록을 제공한다.
   - 기록 행은 날짜, 게임, 결과, 점수, 소요 시간과 게임별 핵심 지표를 표시한다.
   - 로딩, 빈 기록, 오류/재시도 상태를 구현한다.
5. 데이터
   - 기존 authoritative play tables와 게임별 저장소를 우선 재사용한다.
   - 범용 결과 모델이 필요하면 안정된 game kind, session/run identity, participant identity, outcome, score, duration, metrics JSON, completion timestamp와 unique idempotency key를 가진다.
   - 학생 인증·학급 소속·게임 참가 권한을 서버에서 검증하고 클라이언트가 보낸 점수는 신뢰하지 않는다.
   - 근거 없는 과거 전적을 만들지 않는다. 안전하게 변환 가능한 기존 완료 데이터만 명시적으로 마이그레이션한다.
6. 플랫폼
   - 웹과 Expo 모바일에서 같은 상태·행동·결과 의미를 제공한다.
   - 360px 휴대폰, 600~1280px 태블릿, 데스크톱에서 잘림 없이 동작한다.
   - 44×44 이상 터치 영역, 키보드 회피, 포커스, 스크린리더 이름, reduced motion을 보장한다.

## 합격 점수표

총점 100점, 합격선 92점이다.

| 영역 | 배점 | 합격 증거 |
|---|---:|---|
| 공통 게임 생명주기 | 20 | 입장·대기·진행·종료·재도전 상태와 공통 셸 계약 테스트 |
| 데이터 무결성·보안 | 20 | 서버 권위 결과, 중복 방지, 본인 전적 격리, migration/index/API 테스트 |
| 게임 UI/UX | 20 | 레퍼런스 방향, 꼬들 과잉 장식 제거, 반응형·상태·접근성 증거 |
| 개인 전적 경험 | 15 | 웹·모바일 탭, 요약/필터/기록, 로딩·빈·오류 상태 |
| PLAY 5종 적용 완결성 | 15 | 각 게임 입장·종료·결과 기록 매핑과 회귀 테스트 |
| 검증·유지보수성 | 10 | 타입, 단위/통합 테스트, production build, mobile design/export, 문서 |

### 점수와 무관한 필수 통과 조건

- PLAY 5종 중 누락 없음.
- 웹 또는 모바일 중 한 플랫폼만 구현한 상태 금지.
- 꼬들이 기존 보드형/과잉 장식 화면을 유지하면 실패.
- 종료 결과가 클라이언트 입력만으로 확정되거나 중복 기록 가능하면 실패.
- 다른 학생 전적 열람 가능성이 있으면 실패.
- 입장·종료·개인 전적 탭 중 하나라도 없으면 실패.
- 타입 검사, 관련 테스트, production build, 모바일 디자인 검사 또는 Android export 실패 시 불합격.
- production migration 적용, production secret 변경, commit/push는 금지한다.

최종 웹 검수는 영역별 점수와 증거를 기록한다. 92점 미만이거나 필수 조건 실패면 `implementation`으로 되돌려 구체적 결함을 수정하고 다시 채점한다.

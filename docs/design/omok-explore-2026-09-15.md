## 격자 렌더링 제약

D안 판이 계속 세로 줄무늬로 보였다. 원인은 나뭇결이 아니라 인스턴스 구조였다.
공유 `Omok / Board` 마스터의 격자선은 1px인데 인스턴스를 축소하면 0.45~0.83px가
되어 디바이스 픽셀 아래로 내려간다. 그런데 인스턴스 자식의 크기는 오버라이드할
수 없다. `resize()`를 호출해도 값이 마스터로 되돌아간다
(`This property cannot be overridden in an instance: relative-transform`도 같은
제약이다).

마스터를 고치면 승인된 READY 기준선 4화면까지 함께 바뀌므로 손대지 않았다.
대신 D안에서는 마스터의 격자선과 화점을 `visible = false`로 숨기고 스테이지에
선명한 격자 오버레이를 따로 그렸다(웹 262:472, 모바일 263:1892). 셀 중심 좌표계는
그대로여서 돌 배치는 영향받지 않는다.

이 방식은 판이 컴포넌트 인스턴스인데 격자만 로컬이라는 뜻이다. D안이 확정되면
스케일에 맞는 격자 두께를 갖는 별도 보드 컴포넌트를 만드는 편이 깔끔하다.
구현 쪽은 CSS 셀 테두리를 쓰므로 이 문제가 없다.

## 방향 결정 (2026-09-15)

사용자가 A를 먼저 고른 뒤 "SVG 같다"고 지적했고, 이어서 레퍼런스 이미지를 주며
그 스타일을 요청했다. 그래서 A의 정보 구조를 유지하면서 레퍼런스 톤으로 다시
그린 D안을 만들었고 D를 현재 선택 방향으로 둔다. A·B·C는 비교용으로 남긴다.

"기성 오목 SDK를 넣자"는 요청도 있었지만, 유지되는 전용 오목 보드 패키지가
없었다. react-gomoku는 재사용 컴포넌트가 아닌 완성 앱, tenuki는 바둑 규칙,
renju는 렌더링 없는 규칙 엔진이다. 우리 착수 검증은 이미 Rust play-engine이
권위를 가지므로 외부 규칙 엔진은 판정을 두 곳으로 갈라 놓는다. 따라서 판
렌더링은 기존 그리드를 유지하고 표현만 바꾸기로 했다.

## 실제 자산 사용

"SVG 같다"는 인상의 원인은 판 재질이 아니라 단색 도형 플레이스홀더였다. 그래서
대표펫 자리에 저장소의 실제 스프라이트를 넣었다.

- 원본: `public/creatures/slimes/official/base/{blue,green}/idle/sheet.png`
- 첫 프레임을 잘라 트림 후 정사각 패딩, nearest 6배 확대해 Figma에 업로드
- 나뭇결은 절차적으로 생성했다. 결 간격을 x축으로 적분해 변화를 주고 섬유·기공
  노이즈를 겹쳤다. 초기 두 번은 가로 밴딩과 얼룩이 생겨 세 번째에 해결했다.
- 돌에는 접지 그림자를 넣어 판에 놓인 느낌을 만들었다.
- 생성 스크립트는 `work/omok-assets/`에 있다(커밋 대상 아님).

D안 구현에 필요한 것은 텍스처 PNG 한 장과 색 토큰 교체이며, 대표펫은 이미
`OfficialSlimeSprite`가 같은 스프라이트를 렌더한다.

## 검증

`get_screenshot`과 인라인 `node.screenshot()`으로 6개 프레임과 각 판을 확인했다.
수정한 결함:

1. 인스턴스 `resize()`가 내부 원을 함께 줄이지 않아 돌이 격자보다 컸다. 모든
   돌을 `rescale()`로 셀 크기에 맞췄다.
2. 축소 인스턴스에서 1px 격자선이 디바이스 픽셀 아래로 내려가 절반이 사라졌다.
   보드를 `resize` 대신 `rescale`로 축소하고 선 두께를 보정했다.
3. 조준·호버 표시가 마지막 착수 금색 링과 같은 색이라 구분되지 않았다. A는
   먹색 점선, B는 잉크 점선, C는 시안 발광으로 분리했다.
4. 다크 판에서 흑돌, 흰 판에서 백돌이 배경에 묻혔다. 각각 쿨톤 림과 슬레이트
   테두리를 인스턴스 오버라이드로 넣었다.
5. 착수 기록·최근 착수 좌표가 실제 돌 배치와 달라 셀 좌표로 맞췄다.
6. D안 첫 렌더에서 0.75px 격자선이 디바이스 픽셀 아래로 내려가고 나뭇결 링이
   격자처럼 읽혀 세로 줄무늬만 보였다. 선을 1.4px로 올리고 텍스처 불투명도를
   낮춰 격자가 이기게 했다.
7. A안 국면에서 흑 4목이 이미 막혀 조준점이 승리로 읽히지 않았다. 8행에 양쪽이
   열린 4목을 만들고 백의 마지막 착수를 그 줄 밖으로 옮겼다. 착수 기록은 판을
   되읽어 좌표를 파생하도록 바꿔 다시 어긋나지 않게 했다.

검증하지 않은 것: 실제 브라우저·실기기 렌더링, 포커스 순서, 대비 수치 측정,
애니메이션, 프로토타입 동작.

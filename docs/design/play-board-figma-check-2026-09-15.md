## v2 교사 설정 반영 (2026-09-15)

`SongGuessPoolPicker`의 듣기 구간과 문제 수를 `<select>`에서 눌린 상태를 갖는
버튼으로 바꾸고, 단계 번호(`1 · 2 · 3`), 곡 풀 진행 바, 예상 진행 시간을 더했다.
예상 시간은 문자열을 박아 넣지 않고 `estimateSongGuessDuration`이 권위 규칙의
30초 응답 창(`SONG_GUESS_ANSWER_WINDOW_MS`)에서 계산한다. 같은 상수를 스냅샷
검증기의 리터럴 `30000` 자리에도 넣어 규칙이 갈라지지 않게 했다.

## 확인하지 않은 것

정적 스크린샷과 CSS/TSX 대조만 수행했다. 실제 브라우저 렌더링, 실기기 동작,
포커스 순서, 색 대비 수치, 애니메이션은 확인하지 않았다. 꼬들 승리 토스트의
폭죽·상승 애니메이션은 CSS 키프레임에만 있고 Figma는 정지 상태만 담고 있다.

## 오목 캔버스 생성 (2026-09-15)

오목은 시안이 전혀 없어서 마이그레이션할 대상이 없었다. 그래서 꼬들과 같은
방식으로 현재 구현에서 역으로 캔버스를 만들었다. 색과 치수는 추정하지 않고
`src/components/OmokBoard.module.css`에서 그대로 가져왔다. 판 #d9a65e, 테두리
12px #ad7a42, 격자 rgba(74,46,22,.46), 마지막 착수 #ffca48, 셸 그라디언트
`#effbf7 → #e7f4ff → #f7efff`가 그 예다.

변수는 primitives 23개와 semantic 11개로 나누고, semantic은 alias만 갖는다.
컴포넌트는 `Omok / Stone`(5변형), `Omok / PlayerRow`(4변형), `Omok / Board`
세 개이고, 화면은 모두 인스턴스로 조립했다. 대표펫 자리는 저장소의
`public/creatures/slimes/{blue,green}/idle.gif` 첫 프레임을 4배 nearest 확대해
실제 스프라이트로 채웠다.

돌 배치에서 한 가지를 바로잡았다. 처음에는 격자 교차점에 돌을 놓았는데,
구현은 `grid-template-columns: repeat(15, 1fr)`의 각 칸에 `place-items: center`로
돌을 그린다. 그래서 판의 격자선과 화점, 돌 좌표를 모두 칸 중앙 기준으로 고쳤다.

화면 4개(웹 대국/매칭/결과, 모바일 대국)는 모두 `[WIP]`이다. 무승부, 기권 확정,
관전자, 연결 끊김, 태블릿 브레이크포인트는 아직 없고 `docs/design/omok/figma-manifest.json`의
`gaps`에 남겼다. READY 승격은 사람 승인이 필요하므로 하지 않았다.

## 스피드게임·그림자연합 캔버스 생성 (2026-09-15)

두 게임의 색 체계가 서로 반대라서 변수 구성도 다르게 잡았다.

스피드게임은 전용 팔레트가 없다. `src/styles/speed-game.css`가 `--color-accent`
처럼 앱 전역 토큰만 참조한다. 그래서 게임 전용 primitives를 새로 만들지 않고
`App · Foundations` 컬렉션 20개를 만들어 `src/styles/base.css` 값을 담았다.
같은 토큰을 쓰는 다른 레이아웃이 나중에 재사용할 수 있다. 화면은 교사 라운드
진행과 학생 답변 제출 2개이고, 교사는 제시어를, 학생은 순서 번호만 보는 구현의
역할 분기를 그대로 옮겼다.

그림자연합은 반대로 앱 토큰을 전혀 쓰지 않는 어두운 전용 팔레트를 갖는다.
`.shadow-alliance-game`의 커스텀 속성에서 primitives 18개를 뽑고 semantic 11개를
alias로 연결했다. 판 #08090d, 패널 #141720, 금색 지령 #e4c778, 흑 연합 #7180a4,
백 연합 #f0e5c3이 그 값이다.

폰트에서 한 가지를 확인했다. CSS는 `Nanum Myeongjo`를 먼저 요청하지만 이 파일에
없어서, 추정하지 않고 `listAvailableFontsAsync`로 확인한 뒤 CSS 폴백인
`Noto Serif KR`을 썼다. 브랜드 마크의 `Cinzel`은 파일에 있어 그대로 사용했다.
이 사실은 Design Notes와 매니페스트에 기록했다.

페이지 번호가 겹치는 문제도 정리했다. 꼬들이 이미 14/15를 쓰고 있어서 새로 만든
그림자연합을 16/16.1로 옮겼다. 꼬들 번호는 기존 문서와 매니페스트가 참조하므로
건드리지 않았다.

## 페이지 인덱스를 저장소에 남긴 이유

`get_metadata`를 nodeId 없이 호출하면 페이지가 한 개만 반환된다. 이 때문에 v2
플로우 페이지(99:3, 112:2)를 찾는 데 노드 ID를 여러 번 추측해야 했다. 같은 낭비가
반복되지 않도록 전체 페이지와 변수 컬렉션 ID를
[figma-page-index.json](figma-page-index.json)에 기록했다.
